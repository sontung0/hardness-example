## Findings

### Architecture Delta

**Status: Clean** — No violations found.

The layered architecture (Routes → Services → Store) is maintained correctly:
- `main.py` → `routes.router` (app factory imports router)
- `routes.py` → `auth`, `models`, `services` (routes call services and auth)
- `services.py` → `store` (services call store)
- `store.py` → nothing (leaf node)
- `auth.py` → nothing (leaf node, uses only external libs)
- `models.py` → nothing (leaf node, pure Pydantic models)

No cross-layer violations. No cycles introduced.

### Duplication Map

**Finding D-1: Username normalization at multiple layers** — *Accept*
- **Source:** `src/services.py:9,20`, `src/routes.py:20`, `src/auth.py:16`
- **Description:** `username.lower()` is called in three places:
  - `services.py:9,20` — normalizes on write (correct per architecture)
  - `routes.py:20` — normalizes when creating token after registration (redundant with services)
  - `auth.py:16` — normalizes when creating token (correct — auth module should normalize)
- **Disposition:** Accept as-is. The redundancy in `routes.py:20` is harmless (calling `.lower()` on an already-lowered string), and `auth.py:16` is correct because it's the token creation layer. No action needed.

**Finding D-2: Test payload construction** — *Fix now*
- **Source:** `tests/test_auth.py` — 38 inline `json={...}` vs 22 `registration_payload()` calls
- **Description:** Login payloads are constructed inline 11+ times with no factory, despite a registration factory existing. This creates maintenance drift risk.
- **Disposition:** Fix now. Add a `login_payload()` factory to `tests/support/helpers/factories.py` and migrate login test payloads.
