- (assumption) Framework: FastAPI (Python) — PRD leaves open; Python venv available in workspace. Tagged [ASSUMPTION] in spine for user correction.
- (decision) AD-1: Statelessness — all auth state carried in JWT; no server-side sessions. Binds: auth flow, GET /me. Prevents: session-store drift between units.
- (decision) AD-2: Password hashing — bcrypt with default work factor; plaintext password must never persist or appear in responses. Binds: /register, /login. Prevents: plaintext credential storage.
- (decision) AD-3: Single in-memory user store — Python dict keyed by username; no persistence, no database. Binds: all endpoints. Prevents: hidden persistence assumptions.
- (decision) AD-4: JWT as sole auth mechanism — signed token in Authorization header; no refresh tokens, no session cookies. Binds: /me, middleware. Prevents: mixed auth strategies.
- (decision) AD-5: Error responses — consistent HTTP status codes + JSON body with detail field. Binds: all endpoints. Prevents: inconsistent error shapes across units.
- (constraint) PRD scope: no persistence, no refresh tokens, no rate limiting, no HTTPS, no RBAC. These are intentional non-goals, not gaps.

- (decision) AD-9: Password Change Gate — current password must be verified before accepting a new one. New password min 8 chars, no complexity rules. Existing JWT remains valid after change (no token rotation). Binds: POST /change-password, services layer. Prevents: unauthorized password takeover, weak password acceptance, unnecessary token invalidation.
- (decision) AD-10: Password Change Error Semantics — wrong current password returns 401 (same status as unauthenticated) with generic message. No distinction between 'user not found' and 'wrong password'. New password too short returns 400. Binds: POST /change-password, error responses. Prevents: user enumeration via differential error messages.
- (decision) AD-11: Store Mutation for Password Change — store.py gets an update_password(username, new_hash) function. Re-hashes in services layer, store only writes the new hash. Same pattern as add_user: services owns logic, store is a dumb writer. Binds: services.py, store.py. Prevents: store layer doing bcrypt work, double-hashing.
